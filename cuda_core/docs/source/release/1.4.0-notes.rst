``cuda.core`` 1.4.0 Release Notes
=================================

Fixes and enhancements
----------------------

- Kernels, :meth:`Buffer.fill` and asynchronous copies now work on
  :class:`PinnedMemoryResource` buffers in a process that imported the pool,
  through :meth:`PinnedMemoryResource.from_allocation_handle` or by
  unpickling. Pool access is per process, and ``cuda.core`` 1.3.0 granted
  device access only in the creating process, so in an importing process
  kernels failed with ``CUDA_ERROR_ILLEGAL_ADDRESS``, ``fill`` failed with
  ``CUDA_ERROR_INVALID_VALUE``, and copies silently blocked the host until
  earlier work on the stream completed. The importing process now grants the
  device that is current when it imports the pool, or device 0 if no device
  is current, read and write access.
  (`#3501 <https://github.com/NVIDIA/cuda-python/issues/3501>`__)
