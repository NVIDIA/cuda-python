Migrating to the _v2 Bindings#

The cuda.bindings._v2 package provides new bindings for the CUDA driver API (driver_v2) and NVRTC (nvrtc_v2). They cover the same C APIs as the existing driver and nvrtc modules but follow a more Pythonic design. This guide lists what changed so that existing code can be ported.

Overview of changes#

Errors are raised as exceptions#

Legacy functions return a tuple that starts with a result code, such as (CUresult.CUDA_SUCCESS, value). The new functions never return a result code. A failing call raises an exception instead. The exceptions derive from DriverError for the driver and NvrtcError for NVRTC, and there is one subclass per error code, for example InvalidDeviceError. The numeric status is available as e.status (a plain int).

Return values#

A function with no outputs returns None, a function with one output returns that value directly, and a function with several outputs returns a tuple. The order of the outputs is the same as in the legacy API. Functions whose signature or return value changes beyond this are noted in the tables below.

Naming#

  • Functions use snake_case with the cu/nvrtc prefix removed (cuStreamCreate becomes stream_create). Driver functions keep the version suffix of the C symbol (mem_alloc_v2), whereas the legacy module drops it.

  • Parameters and struct members use snake_case. A parameter that is a Python keyword gets a trailing underscore (from_). Python builtin names such as type and object are kept as they are. A struct member whose name would shadow an attribute of the class (ptr) or of the NumPy array that backs struct arrays (data, flags, size, device) also gets a trailing underscore (flags_, data_).

  • Enumeration classes and structs use CamelCase with the CU/nvrtc prefix removed. Structs keep their C version suffix (MemLocation_v1) and there is a single class per versioned C type instead of several aliases.

  • Enumeration members lose their common C prefix (CU_DEVICE_ATTRIBUTE_MAX_THREADS_PER_BLOCK becomes DeviceAttribute.MAX_THREADS_PER_BLOCK), and the old full names are not kept as aliases. Enumerations with a single member keep the part of the C name that identifies the member, because there is no second member to share a prefix with. For example CU_IPC_MEM_LAZY_ENABLE_PEER_ACCESS becomes IpcMemFlags.IPC_MEM_LAZY_ENABLE_PEER_ACCESS and CU_USER_OBJECT_NO_DESTRUCTOR_SYNC becomes UserObjectFlags.USER_OBJECT_NO_DESTRUCTOR_SYNC. The Prefix removed columns below list what was removed in each case.

Handles are plain integers#

Handle types such as CUcontext, CUstream, CUevent, CUmodule, CUdeviceptr and nvrtcProgram are no longer classes. Functions return them as int and accept only int. Legacy functions accepted None for a null handle. The new functions raise TypeError for None; pass 0 instead (for example stream_synchronize(0) for the default stream). Use int(handle) to convert a legacy handle object.

Enumerations#

Enumeration classes are int subclasses. Functions accept either the enumeration members or plain integers. Their members expose a description of the value automatically, so the individual members are no longer documented one by one.

Structs#

Struct classes are generated extension types that wrap a C struct. They expose their address through the .ptr property (replacing getPtr()), and can be created from existing memory with the from_ptr(), from_data() (which takes a NumPy array of the matching *_dtype) and from_buffer() class methods. Where a function takes a struct, the argument is either a raw address (an int) or the struct object itself. Wrapper objects of the legacy classes cannot be passed in their place.

Strings and constants#

  • get_error_string and get_error_name return str, where the legacy functions returned bytes.

  • The #define constants that the legacy driver module exposed as module attributes (CU_MEMHOSTALLOC_PORTABLE and so on) are now members of enumerations grouped by purpose, for example MemHostAllocFlags.PORTABLE. Only a few ungrouped constants remain at module level, keeping their C names: CUDA_VERSION, CU_IPC_HANDLE_SIZE, CU_TENSOR_MAP_NUM_QWORDS, CU_LAUNCH_KERNEL_REQUIRED_BLOCK_DIM, CUDA_EGL_INFINITE_TIMEOUT and MAX_PLANES.

Driver#

The cuda.bindings._v2.driver module replaces cuda.bindings.driver. The deprecated driver APIs (texture references, surface references, cuLaunch* and cuParam* functions, cuCtxAttach, and so on) are also available and follow the same rules. They are listed in the Deprecated functions table below.

Functions#

Where the C symbol has a version suffix (cuCtxCreate_v2), the legacy module generally exposes only the unsuffixed name, while the new module keeps the suffix, so one legacy function can map to several new ones. A few legacy functions (cuCtxGetDevice_v2 and similar) already carry the suffix. They have their own rows and map to the new function of the same name. Only changes to parameters and return values beyond the general rules above are noted. Renamed parameters are not listed.
