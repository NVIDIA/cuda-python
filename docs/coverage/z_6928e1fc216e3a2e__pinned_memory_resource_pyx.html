75 Parameters 

76 ---------- 

77 options : PinnedMemoryResourceOptions 

78 Memory resource creation options. 

79  

80 If set to `None`, the memory resource uses the driver's current 

81 stream-ordered memory pool. If no memory 

82 pool is set as current, the driver's default memory pool 

83 is used. 

84  

85 If not set to `None`, a new memory pool is created, which is owned by 

86 the memory resource. 

87  

88 When using an existing (current or default) memory pool, the returned 

89 host-pinned memory resource does not own the pool (`is_handle_owned` is 

90 `False`), and closing the resource has no effect. 

91  

92 Notes 

93 ----- 

94 The device associated with ``stream`` must support host memory pools. If 

95 ``numa_id`` is set or derived for IPC, it must support host NUMA memory pools. 

96 You can query these capabilities through 

97 ``Device.properties.host_memory_pools_supported`` and 

98 ``Device.properties.host_numa_memory_pools_supported``. If the required pool 

99 is unsupported and stream-ordered allocation is not needed, use 

100 :class:`LegacyPinnedMemoryResource`. 

101  

102 To create an IPC-Enabled memory resource (MR) that is capable of sharing 

103 allocations between processes, specify ``ipc_enabled=True`` in the initializer 

104 option. When IPC is enabled and ``numa_id`` is not specified, the NUMA node 

105 is automatically derived from the current CUDA device's ``host_numa_id`` 

106 attribute, which requires an active CUDA context. If ``numa_id`` is 

107 explicitly set, that value is used regardless of ``ipc_enabled``. 

108  

109 See :class:`DeviceMemoryResource` for more details on IPC usage patterns. 

110 """
