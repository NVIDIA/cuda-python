5"""The cuda-bindings version floor: how it is read and how it is enforced. 

6 

7cuda.core supports two CUDA major series at a time. For each series, it 

8requires a minimum cuda-bindings version, the *floor*, at build time and at 

9run time. The floor is the newest cuda-bindings release of that series at the 

10time of the cuda.core release. Normally that is the release that the cuda.core 

11wheels are built against. See https://github.com/NVIDIA/cuda-python/issues/2783 

12and the support policy in the documentation. 

13 

14Exactly one place declares the floors: the ``cu12`` and ``cu13`` extras in 

15``pyproject.toml``. Each extra pins ``cuda-bindings>=<floor>,<<next major>``. 

16Everything else derives from them through :func:`floors_from_extras`: 

17 

18- The build backend, ``build_hooks.py``, checks the installed cuda-bindings 

19 against the floor. It checks that the ``cuda.h`` that it compiles against is 

20 the one that cuda-bindings was generated from. It passes the floor to the 

21 ``_build_info`` extension module, which records it next to the header the 

22 compiler used. 

23- ``cuda/core/__init__.py`` checks the installed cuda-bindings against that 

24 record with :func:`check_installed_bindings`. 

25- The documentation reads the floors into substitutions in ``docs/source/conf.py``. 

26- ``toolshed/check_cuda_core_bindings_floor.py``, a pre-commit hook, checks 

27 that the CI toolkit pins in ``ci/versions.yml`` sit in the minors of the floors. 

28 

29The build and the tools above load this module by file path. It therefore uses 

30the standard library only and must not import anything from ``cuda``. 

31"""
