77 """Enqueue a host function on a stream in stream order. 

78  

79 The function runs on a driver-owned thread once all work enqueued on the 

80 stream before this call has completed. Work enqueued after this call waits 

81 until the function returns. This call returns when the function is enqueued; 

82 observe completion with :meth:`Stream.sync` or an :class:`Event` recorded 

83 after it. 

84  

85 Passing a :class:`~graph.GraphBuilder` forwards to 

86 :meth:`~graph.GraphBuilder.callback`. 

87  

88 Parameters 

89 ---------- 

90 stream : Stream or graph.GraphBuilder or IsStreamType 

91 The stream establishing execution order, or a graph builder capturing 

92 the callback. 

93 fn : callable or ctypes function pointer 

94 A Python callable taking no arguments, which runs with the GIL, or a 

95 ctypes function pointer declared as ``CUhostFn``, for example 

96 ``ctypes.CFUNCTYPE(None, ctypes.c_void_p)``, which ``cuda.core`` 

97 passes to the driver as is. A pointer to compiled code runs without 

98 the GIL; a ctypes callback that wraps a Python function acquires the 

99 GIL through ctypes and is subject to the same deadlock rule as a 

100 Python callable. :data:`HOST_COPY_FN` is such a pointer, for a host 

101 copy that runs without the GIL. ``cuda.core`` keeps ``fn`` alive until 

102 the function has run and releases it afterwards on the main thread. 

103 user_data : int or bytes-like, optional 

104 Only for ctypes function pointers. An ``int`` is a raw pointer that 

105 the caller must keep valid until the function has run. Bytes-like data 

106 is copied; ``cuda.core`` owns the copy until the function has run and 

107 releases it afterwards on the main thread. 

108  

109 Raises 

110 ------ 

111 TypeError 

112 If ``stream`` is ``None`` or not a stream, or if ``fn`` is not 

113 callable or its ctypes prototype is not ``CUhostFn``. 

114 ValueError 

115 If ``user_data`` is given for a Python callable, or if ``fn`` is 

116 :data:`HOST_COPY_FN` and ``user_data`` is not a packed record. 

117 RuntimeError 

118 If ``stream`` is a :class:`Stream` that is capturing a graph, or a 

119 :class:`~graph.GraphBuilder` that is closed or not building. 

120  

121 Notes 

122 ----- 

123 An exception raised by a Python callable cannot propagate to the caller. 

124 It is reported through :func:`sys.unraisablehook` and the stream continues. 

125  

126 .. warning:: 

127  

128 The function must not call CUDA, directly or through a library. The 

129 driver does not permit such calls. Such a call may fail with an error, 

130 or it may deadlock. 

131  

132 A Python callable, or a ctypes callback that wraps a Python function, 

133 acquires the GIL on the driver's thread. A thread 

134 that holds the GIL while blocking inside a CUDA call waiting for this 

135 stream therefore deadlocks with the callback. ``cuda.core`` and 

136 ``cuda.bindings`` release the GIL around CUDA calls. A library that 

137 calls CUDA with the GIL held must not be used to wait on a stream with 

138 a pending Python callback. 

139 """
