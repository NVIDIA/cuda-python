181 """Serializable object describing a :class:`VirtualMemoryBuffer` that can be shared between processes. 

182  

183 The descriptor holds one exported POSIX file descriptor per physical 

184 allocation that backs the buffer, in address order (``handles``, each an 

185 :class:`IPCAllocationHandle` that the descriptor owns and closes when it 

186 is released), with each allocation's size (``sizes``) and the buffer's 

187 size (``size``, which may be smaller than their sum). ``handle_type`` is 

188 ``"posix_fd"``, the only handle type cuda.core shares today; the rules 

189 below describe file descriptors. 

190  

191 A descriptor pins the physical memory while it exists, in every process 

192 that holds one, and nothing else does: the exporting buffer keeps no 

193 descriptor, and an imported buffer does not keep the one it came from. A 

194 descriptor parked in a ``multiprocessing`` ``Queue`` or sent to a ``Pool`` 

195 pins the memory in the sender until the receiver has unpickled it; a 

196 buffer passed as a ``Process`` argument pins it until the ``Process`` 

197 object is released, because the child receives the file descriptors when 

198 it is spawned. 

199  

200 Two transports exist. ``multiprocessing`` (a ``Queue``, a ``Pipe``, 

201 ``Process`` arguments, or a ``Pool``) pickles the descriptor, or a buffer, 

202 and duplicates the file descriptors into the receiving process; plain 

203 ``pickle`` cannot carry them and raises. A process with its own file 

204 descriptor passing sends ``fds``, ``sizes``, and ``size`` itself, and the

206  

207 Note 

208 ---- 

209 The sizes are controlled by the exporting peer. Receivers must treat them
