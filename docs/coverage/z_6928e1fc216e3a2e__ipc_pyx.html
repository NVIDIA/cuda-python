49# Maps uuid.UUID.bytes to a weakref.KeyedRef of the registered resource. The key 

50# is bytes so that the dict hashes and compares it in C, without running Python. 

51cdef dict registry = {} 

52# Guards every access to the registry, reads included. Without the GIL a read 

53# needs it for two reasons. Cython reads a typed dict through a borrowed 

54# reference, which a concurrent removal can free before the read takes its own 

55# reference. And a registration inserts the entry and then sets the handle's 

56# UUID, so a reader must not run between the two. 

57# 

58# No Python code may run while it is held: a collection can start in Python 

59# code, and its callbacks and finalizers can register or drop resources on this 

60# thread. That includes hashing or comparing a uuid.UUID, calling a 

61# WeakValueDictionary method, raising, and dropping the last reference to a 

62# resource. Anything that can run Python goes before the lock, and errors are 

63# raised after it is released. One exception remains: if the insertion fails 

64# (for example with MemoryError), building the traceback allocates objects, 

65# which on Python 3.11 can start a collection under the lock. 

66cdef object _registry_lock = threading.RLock()

258cdef class VirtualMemoryFdBufferDescriptor(_VirtualMemoryDescriptor): 

259 """Serializable object describing a :class:`VirtualMemoryBuffer` that can be shared between processes. 

260  

261 The descriptor holds one exported POSIX file descriptor per physical 

262 allocation that backs the buffer, in address order (``handles``, each an 

263 :class:`IPCAllocationHandle` that the descriptor owns and closes when it 

264 is released), with each allocation's size (``sizes``) and the buffer's 

265 size (``size``, which may be smaller than their sum). ``handle_type`` is 

266 ``"posix_fd"``; the rules below describe file descriptors. 

267  

268 A descriptor pins the physical memory while it exists, in every process
