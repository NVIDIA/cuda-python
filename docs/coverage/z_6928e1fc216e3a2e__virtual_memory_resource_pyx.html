385cdef class VirtualMemoryResource(MemoryResource): 

386 """Create a device memory resource that uses the CUDA VMM APIs to allocate memory. 

387  

388 Parameters 

389 ---------- 

390 device_id : Device | int 

391 Device for which a memory resource is constructed. 

392  

393 config : VirtualMemoryResourceOptions, optional 

394 A configuration object for the VirtualMemoryResource 

395  

396  

397 Warning 

398 ------- 

399 This is a low-level API that is provided only for convenience. Make sure you fully understand 

400 how CUDA Virtual Memory Management works before using this. Other MemoryResource subclasses 

401 in cuda.core should already meet the common needs. 

402  

403 A shared buffer's descriptor comes from the exporting process and is not trusted: 

404 :meth:`Buffer.from_ipc_descriptor` checks what it can, and the driver rejects a size that 

405 does not match the exported allocation. Unpickling a shared buffer performs a live import, 

406 so unpickle buffers only from a trusted principal. A descriptor pins the physical memory 

407 while it exists; release it when the receiver has imported it. 

408  

409 Notes 

410 ----- 

411 Every buffer this resource returns is a :class:`VirtualMemoryBuffer` that 

412 owns its address reservations, physical allocations and mappings; closing 

413 the buffer releases them. :meth:`deallocate` is not involved in that path. 

414  

415 Virtual memory is unmapped synchronously, so closing a buffer waits for 

416 the work queued on its deallocation stream. A buffer released by the 

417 garbage collector waits at that point instead. To control when the wait 

418 happens, close the buffer explicitly or record an idle stream with 

419 :meth:`Buffer.set_deallocation_stream`. 

420  

421 Buffers can be shared with other processes when ``config.handle_type`` 

422 is ``"posix_fd"`` (Linux), the only handle type cuda.core shares today; 

423 ``handle_type`` is the switch and :attr:`is_ipc_enabled` the query. The 

424 rules that follow describe POSIX file descriptors. 

425 :attr:`Buffer.ipc_descriptor` exports the physical allocations that back 

426 a buffer, one file descriptor each, into a new descriptor on every 

427 access; :meth:`Buffer.from_ipc_descriptor` imports a descriptor with a 

428 ``VirtualMemoryResource`` of the receiving process for the device that 

429 owns the memory; and a buffer sent through ``multiprocessing`` does both. 

430 Plain ``pickle`` cannot carry the file descriptors; a process with its 

431 own file descriptor passing sends the descriptor's ``fds``, ``sizes``,
