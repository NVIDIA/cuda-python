``cuda-pathfinder`` 1.9.0 Release notes
=======================================

Compatibility note
------------------

Header, binary utility, static library, and bitcode library lookups now return
resolved absolute paths. Symlinks are followed, so returned paths can differ
from the configured alias, including the basename of a symlinked file.
The ``filename`` fields of :class:`LocatedStaticLib` and
:class:`LocatedBitcodeLib` continue to report the filename searched for.
Public return types, search order, and cache lifetimes are unchanged.
This minor release reflects the intentional change in returned path spelling.

Bugfixes
--------

* Return absolute static-library and bitcode-library paths for relative wheel,
  Conda, and CUDA Toolkit roots, keeping cached results valid after a change
  of working directory. Resolve Windows drive-relative roots such as
  ``D:toolkit`` correctly, including on Python 3.11.
  (`Issue #3363 <https://github.com/NVIDIA/cuda-python/issues/3363>`_,
  `PR #3418 <https://github.com/NVIDIA/cuda-python/pull/3418>`_)

* Preserve the filesystem meaning of roots containing a symlink followed by
  ``..``. Header and binary utility lookups return the selected component's
  resolved path, and dynamic-library directory discovery no longer collapses
  these roots lexically into a different location.
  (`Issue #3413 <https://github.com/NVIDIA/cuda-python/issues/3413>`_,
  `PR #3418 <https://github.com/NVIDIA/cuda-python/pull/3418>`_)

* On Linux, preload ``libnvrtc-builtins.so.<major>.<minor>`` from the same
  directory as NVRTC when loading from a CUDA Toolkit install, so that
  compilation works without ``LD_LIBRARY_PATH`` or an ``ldconfig`` entry
  for the toolkit directory. Wheels keep only the existing NVRTC 13.0
  workaround, and Conda packages are left unchanged.
  (`PR #3439 <https://github.com/NVIDIA/cuda-python/pull/3439>`_)

Documentation
-------------

* Correct the Windows DLL search documentation: native system search normally
  includes ``PATH``, subject to process DLL search policy
  (`packaged applications have a different default DLL search order
  <https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order#search-order-for-packaged-apps>`_).
  ``CUDA_PATH`` and ``CUDA_HOME`` remain fallback discovery roots, not runtime
  toolkit selectors. Loading behavior and search order are unchanged.
  (`Issue #3137 <https://github.com/NVIDIA/cuda-python/issues/3137>`_)
